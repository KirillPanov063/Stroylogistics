5. Бизнес-логика
5.1. Автоматическая нумерация заявок
Нумерация начинается с 1

Каждая новая заявка получает номер на 1 больше предыдущей

Номера не должны повторяться

При удалении заявки номер не переиспользуется

Реализация через последовательность в PostgreSQL

5.2. Правила доступа к заявкам
Пользователь может видеть и редактировать только свои заявки

Администратор видит и может редактировать все заявки

Заявка при создании привязывается к ID пользователя

Проверка прав доступа на уровне middleware

5.3. Валидация данных
Телефоны: российский формат (+7 XXX XXX-XX-XX)

Email: стандартная валидация формата

Сумма оплаты: только положительные числа

Обязательные поля должны быть заполнены

Валидация на фронтенде и бэкенде

6. API Эндпоинты
6.1. Аутентификация
POST /api/auth/register - Регистрация

POST /api/auth/login - Вход

POST /api/auth/logout - Выход

POST /api/auth/refresh - Обновление токена

6.2. Заявки
GET /api/orders - Список заявок (с фильтрами)

GET /api/orders/:id - Получить заявку

POST /api/orders - Создать заявку

PUT /api/orders/:id - Обновить заявку

DELETE /api/orders/:id - Удалить заявку

6.3. Водители
GET /api/drivers - Список водителей

POST /api/drivers - Создать водителя (admin)

PUT /api/drivers/:id - Обновить водителя (admin)

DELETE /api/drivers/:id - Удалить водителя (admin)

6.4. Пользователи
GET /api/users/profile - Профиль текущего пользователя

GET /api/users - Список пользователей (admin)

PUT /api/users/:id - Обновить пользователя (admin)
